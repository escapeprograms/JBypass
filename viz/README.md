# viz

Interactive J-space viewer. Pick a question first (dataset, split, example or a random one, prompt field and one ablation condition, `none` = clean run), then a model (the session profile or one of its saved adapters in `runs/`) and press Run; the model generates, and the J-lens readout of every layer over the prompt and the response is shown as jlens's heatmap page (position x layer grid, top-n on click, rank charts for tracked tokens, with the bridge (English spellings and its single-token Chinese spellings) and the answers pinned), once through the original (prefit) lens and once through the model's own refit lens if one has been fitted, in two tabs. A table lists every model already run on the selected question.

Depends on `evaluation/` (conditions, items, scoring), `jspace/` (readout) and `model/` (loading, inference). Only `app.py` and `run_app.py` import gradio; the rest is plain Python and tested in `tests/test_viz.py`. Settings live in `configs/viz.yaml`.

## How one run works
1. `run.run_example`: encode the prompt, greedy-decode under the condition (same decoding and scoring as eval) -> `prompt_ids + response_ids`, plus `answer_index` (the first response token that is not whitespace, a quote or a filler word); the shown sequence is `prompt_ids + shown_ids`, i.e. the prompt and the response up to and including the answer token.
2. `slice.run_slices`: rebuild the condition's interventions once on the shown sequence (always from the original lens), one forward pass, capture the post-intervention residual at every readout layer of every reader (the original-lens JSpace, and the refit-lens one if loaded).
3. Per reader and layer: transport by that reader's J_l, unembed -> top-n ids and tracked-token ranks -> one `jlens.vis.SliceData` per reader (same outputs as `jlens.vis.compute_slice`, but on our own ids).
4. `page.slice_page` -> self-contained HTML (`build_page(mode="embed")`) per reader; when a dictionary is loaded, `gloss.gloss_payload` + `page.with_glosses` add the translation box (each page its own payload); shown via `page.iframe`. `slice.replay_mismatches` checks the original lens's final row's top-1 reproduces every shown generated token.

Rows at ablated layers show the post-edit residual (under `bridge` the bridge is projected out there by construction). The refit lens is readout-only: generation, the ablations (built from the original lens, whose statistics the clamp caps come from) and the replay check never use it. The final-layer row is the model's own output, so it is the same in both tabs.

## Refit lenses
A model's refit lens is the file `<lenses_dir>/<adapter folder name>.pt` (`lenses_dir` in `configs/viz.yaml`, default `lenses/`), or `<lenses_dir>/<profile>.pt` for a base model (a base-model refit is a control: same recipe as the adapter fits, unlike the prefit lens). Lenses are found at startup, so restart the viewer after fitting one. A model without one shows, in the "Refit lens (this model)" tab, the `python -m jspace.fit_lens` command that fits it (recipe and timing: `commands.md` section 7). A lens is paired with its model by file name only (debt 003).

## Translation box (click a Chinese token)
Clicking a token in the By Layer / By Pos lists, a pinned chip, the prompt strip, or a grid cell opens a box at the bottom right with the token, then per word its pinyin (tone numbers, as stored) and numbered senses. Other scripts (Kana, Hangul, Cyrillic, ...) show "no dictionary entry (CC-CEDICT covers Chinese only)"; Chinese characters with no entry show "no dictionary entry"; English, punctuation and undecodable tokens hide the box. × closes it. jlens's own click behaviour (pin toggle, selection) is unchanged: the box only listens. Not translated: the hover tooltip, the grid's cell text and the x-axis labels. Longest-match splitting is not real word segmentation, so long fragments can split oddly.

Translations come from CC-CEDICT, read once at startup from `dictionary_file` in `configs/viz.yaml` and embedded per page (only the page's foreign tokens; tens of KB per page). **Download it by hand:** save `cedict_1_0_ts_utf-8_mdbg.txt.gz` from https://www.mdbg.net/chinese/dictionary?page=cc-cedict into `downloads/` at the repo root (the site prohibits scripted access, so there is no download command). With the file missing, startup stops with an error saying where to put it; `dictionary_file: null` turns the box off. License and attribution: `NOTICE`.

## Files
- `__init__.py` — package docstring only; imports nothing (so the core works without gradio).
- `config.py` — viewer settings.
  - `VizConfig` — frozen: `runs_dir`, `lenses_dir` (refit lenses), `split_file` (or None), `dictionary_file` (or None = no translations), `top_n`, `max_tracked` (or None = all), `page_height`, `server_name`, `server_port`.
  - `load_viz_config(path=DEFAULT_VIZ_CONFIG)` — read the YAML; `runs_dir` / `lenses_dir` / `split_file` / `dictionary_file` resolved against the file's folder; `null` -> None (`_optional_path`).
  - `DEFAULT_VIZ_CONFIG` — path of `configs/viz.yaml`.
- `catalog.py` — what can be chosen (file access only); invalid combinations are filtered out, never caught.
  - `ModelChoice(profile, adapter=None, lens=None)` — frozen; `lens` is the model's refit lens file (None = none found); `.label` is `"qwen3-1.7b"` or `"qwen3-1.7b + <adapter folder>"` (the lens does not change it).
  - `lens_profiles(profiles_dir)` — sorted profile names with a `prefit_lens`.
  - `model_choices(profiles_dir, runs_dir)` — each lens profile, then each `runs_dir/*/` whose saved profile (`model.lora.PROFILE_FILE`) is a lens profile; a missing `runs_dir` gives just the profiles. `lens` is left None.
  - `refit_lens_file(choice, lenses_dir)` — `<lenses_dir>/<adapter folder name>.pt`, or `<lenses_dir>/<profile>.pt` for a base model (`TODO(debt-003)`: pairing by file name only).
  - `with_refit_lenses(choices, lenses_dir)` — the choices with `.lens` set where `refit_lens_file` exists.
  - `fit_command(choice, lens_file)` — `python -m jspace.fit_lens --model <profile> [--adapter <folder>] --out <lens_file>`, shown when a model has no refit lens.
  - `ALL_SPLITS` — `"all"`, the split choice meaning no split filter.
  - `split_names(items, split_file)` — `ALL_SPLITS` plus each split in the file naming at least one item; `[ALL_SPLITS]` when `split_file` is None.
  - `examples(tokenizer, dataset, split, eval_cfg, split_file)` — the dataset's items in the split whose bridge (and `swap_to`) has a single-token spelling under `tokenizer` (`tokenizer_readable_items`; no model needed).
  - `valid_fields(item, fields)` — the prompt fields that are not None on the item.
  - `NEEDS_SWAP` — the conditions built from `item.swap_to` (`wrong_bridge`, `wrong_bridge_clamp`).
  - `valid_conditions(item, conditions)` — drops the `NEEDS_SWAP` conditions when the item has no `swap_to`.
  - `buildable_conditions(has_stats, item, conditions)` — `valid_conditions`, minus `evaluation.conditions.NEEDS_STATS` (the clamp conditions) when `has_stats` is False (the app passes whether the session profile's readout statistics file exists; run `python -m evaluation.run_readout_stats` with the same `--config` to get `<readout_stats_dir>/<model>.pt`).
  - `pick_random(items, rng)` — one item from a `random.Random`.
- `session.py` — at most one model in memory.
  - `Loaded(js, own=None)` — frozen: `js` the JSpace with the original (prefit) lens, which drives generation, interventions and the replay check; `own` the same JSpace reading through the model's refit lens (readout-only), or None. `.readers` = `[js]` or `[js, own]`.
  - `attach_refit(js, lens_file)` — `Loaded(js, dataclasses.replace(js, lens=load_lens(js.lm, lens_file)))` (same model, lens view, band and statistics; the `run_mechanism --extra_lens` pattern), or `Loaded(js)` for None. `TODO(debt-003)`: the lens is not checked to belong to this model.
  - `Session(load)` — `.get(choice)` returns the cached `Loaded` for the current choice, else releases it and calls `load(choice)`; `.release()` drops the model, runs `gc.collect()` and empties the CUDA cache. Switching adapters reloads the whole model.
  - `make_loader(run, device)` — `choice -> attach_refit(load_frozen_jspace(profile, jspace_config(run), choice.adapter), choice.lens)` with the profile from `run.profiles_dir`, on `device` (None = the profile's device), using the profile's prefit lens, the band of `run`'s `jspace:` section (`--config configs/exp3.yaml` = layers 8-26) and `<readout_stats_dir>/<model>.pt` if present.
- `cache.py` — rendered results of the selected question (plain Python; no gradio, no torch).
  - `RunKey(dataset, name, field, condition, model)` — frozen; `model` is the dropdown label; `.question` = `(dataset, name)`.
  - `Shown(summary, original, own, response, correct)` — frozen, strings and a bool only: the summary markdown (naming the model), the heatmap iframe HTML under the original (prefit) lens, the refit-lens iframe HTML (or the no-refit-lens note), the full response, the eval verdict.
  - `ResultCache()` — `.get(key)` pure lookup (None if absent); `.put(key, shown)` stores it, first dropping every entry if the cache holds another question; `.entries(question)` the `(key, shown)` pairs of that question in insertion order. Unbounded within one question (`TODO(debt)`).
- `run.py` — one generation.
  - `RunResult` — frozen, plain Python values only: `item, field, condition, seed, prompt, prompt_ids, response_ids, response_text, answers, correct, answer_index` (`answer_index` indexes `response_ids` at the token scoring compares against, from `evaluation.scoring.answer_index`). Property `shown_ids` = `response_ids[:answer_index + 1]`, what the heatmap shows after the prompt.
  - `run_example(js, item, field, condition, seed, max_new_tokens)` — greedy-decode the item's field under the condition; text decoded and scored exactly as `evaluation.runner.score_one` does.
- `slice.py` — token ids -> `jlens.vis.SliceData` (tensors only, no HTML).
  - `pinned_tokens(js, result)` — sorted ids of the bridge's single-token English variants (`token_variants`), the single-token Chinese spellings from the item's `bridge_zh` (`jspace.single_token_ids`), and the answers' first tokens. Multi-token Chinese spellings are not pinned (pinning their first character would mislead).
  - `slice_from_ids(js, enc, interventions, top_n, max_tracked, pinned)` — one forward (`forward_residuals`) over a single unpadded row with the interventions at js's readout layers, then `slice_from_resids`.
  - `slice_from_resids(js, enc, resids, top_n, max_tracked, pinned)` — from residuals already captured (at least at js's readout layers): per readout layer (`readout_layers`: fitted layers + final) top-n ids through js's lens, then tracked tokens (jlens's sum-of-1/(rank+1) rule capped by `max_tracked`, plus `pinned`), then their full-vocab ranks. Logits are made one layer at a time.
  - `shown_encoding(js, result)` — `prompt_ids + shown_ids` (prompt + response up to the answer token) as one unpadded `Encoded` row on js's device.
  - `run_slices(js, readers, result, top_n, max_tracked)` — one `SliceData` per reader from a single forward pass: the condition's interventions built once from `js` on `shown_encoding`, residuals captured at the sorted union of the readers' readout layers, each reader read out with `slice_from_resids`; the bridge/answers pinned.
  - `run_slice(js, result, top_n, max_tracked)` — `run_slices(js, [js], ...)[0]`.
  - `replay_mismatches(slice_data, result)` — indices into `shown_ids` whose generated token is not the final layer's top-1 at the previous position; `[]` means the readout reproduces generation (bf16 near-ties on GPU may break this, so it is reported, not raised).
  - `RANK_CHUNK` — positions per full-vocab sort when ranking.
- `cedict.py` — CC-CEDICT, standard library only.
  - `CEDICT_PAGE`, `CEDICT_FILE` — where the dictionary is downloaded (by hand) and the file's name.
  - `Entry(traditional, simplified, pinyin, senses)` — frozen; `pinyin` verbatim, `senses` the `/`-separated senses (`;` stays inside a sense).
  - `Segment(word, entries)` — frozen; `entries == ()` means no dictionary entry.
  - `Cedict(index, max_len, n_entries)` — headword (traditional and simplified) -> its entries in file order, proper nouns (capitalised pinyin) last; longest headword; parsed lines.
  - `parse_line(line)` — one line, either format (`繁 简 [pin1 yin1] /a/b/` or `繁 简 [[pin1yin1]] /a; b/c/`); `ValueError` otherwise.
  - `parse_cedict(lines)` — skips blank and `#` lines; any other bad line raises with its line number; no entries raises.
  - `segment(cedict, text)` — longest match at each position; unmatched characters merge into one entry-less segment; whitespace dropped.
  - `load_cedict(path)` — the only file access (gzip, `utf-8-sig`); a missing file raises naming the path, the download page and `dictionary_file: null`.
- `gloss.py` — which tokens get a translation; the JSON the box reads.
  - `is_foreign(text)` — any letter above U+024F (`LAST_LATIN`), so accented Latin is not foreign.
  - `token_gloss(cedict, text)` — `{"text": stripped token, "segments": [{"word", "entries": [{"reading", "senses"}]}]}`.
  - `gloss_payload(slice_data, cedict)` — `{"context_ids": prompt-strip ids (from ctx_offset), "glosses": {str(id): token_gloss}}` for every foreign token in `vocab_fragment` (a foreign token with no hits still gets a key, so the box can say so).
- `static/gloss.js`, `static/gloss.css` — the box (injected into the page; package data). The script reads token ids from the page's own elements: list cells and pinned chips by `data-tid` (capture-phase listener, since jlens stops propagation there; a chip's × is ignored), prompt-strip tokens by index into `context_ids`, grid cells by reading the active By Layer row's first cell after jlens's own grid handler has re-rendered (bubble phase; ignored unless jlens's hover outline shows the pointer is on a cell). It builds the box with `textContent` only and never stops or cancels an event. Depends on jlens page internals (TODO(debt) at its top; `test_jlens_page_contract` guards it). The CSS sets the box size as custom properties at the top; `z-index` 900, below the page tooltip.
- `NOTICE` — CC-CEDICT source and CC BY-SA 4.0 attribution.
- `page.py` — the only HTML (and, through jlens, network) code.
  - `slice_page(slice_data, result, title)` — `build_page(mode="embed")` HTML; `title` names the model, item and lens (`<label>: <item> | original lens (<n> prompts)` / `refit lens`, from the lens's `n_prompts`), the description gives the condition and field, says positions cover the prompt and the response up to the answer token, and notes that ablated rows show the post-edit residual. The text passed to `build_page` is the joined `context_token_strs` (jlens never renders it). d3 is fetched from a CDN once per process.
  - `with_glosses(page, payload)` — inserts `<style>` (gloss.css), `<script type="application/json" id="jb-gloss-data">` (the payload, `<` escaped as `<`) and `<script>` (gloss.js) before the last `</body>`; raises if there is none.
  - `GLOSS_DATA_ID` — `"jb-gloss-data"`, the data script's id.
  - `iframe(page, height)` — the page in a `srcdoc` iframe (HTML-escaped).
  - `summary(result, mismatches)` — markdown: prompt, bridge (via `bridge_label`), expected answers, response (via `one_line`), correct/incorrect, the shown-positions line (`_shown_line`), and the replay check.
  - `_shown_line(result)` — "Shown response tokens are positions a-b; position b is the answer token (response token k of n)."
  - `one_line(text)` — newlines shown as ⏎ (as the heatmap shows them) so the response stays one markdown line.
  - `no_refit_lens_note(label, command)` — HTML (label and command escaped) for the refit tab of a model with no refit lens: the fit command, and that the viewer must be restarted afterwards.
  - `responses_table(rows)` — markdown table of `ResultCache.entries` rows in run order: Model, Prompt field, Ablation, Response (`one_line`), Correct (yes/no); `""` for no rows. Cells are HTML-escaped with `|` escaped (`_table_row`, `_table_cell`), so a response cannot break the table.
  - `item_card(item, field)` — markdown card for the chosen example before a run: name, category, the field's prompt, bridge (via `bridge_label`), swap bridge, expected answers.
  - `bridge_label(item)` — the bridge followed by its `bridge_zh` spellings in parentheses, e.g. `France (法国, 法兰西)`; just `France` when `bridge_zh` is empty.

## App (`app.py`, `run_app.py`)
Launch from the repo root: `python -m viz.run_app` (flags: `--config`, `--model`, `--device`, `--viz_config`), then open `http://127.0.0.1:7860` (`server_name` / `server_port` in `configs/viz.yaml`). The first run in a process downloads d3 from a CDN (jlens inlines it into the page), so it needs internet once. Needs `gradio==6.32.0` (in `environment.yml`).

At startup it prints the dictionary line (see `load_dictionary`), or stops if `dictionary_file` is set but the file is missing.

Layout, top to bottom: dataset, split / example, Random example / prompt field, ablation / the item card / model, Run / the responses table / summary / two tabs, "Original lens" and "Refit lens (this model)", each a heatmap page (the refit tab shows the fit command when the model has no refit lens).

UI flow: the page opens without loading a model (startup loads only the session profile's tokenizer, which the question list needs). On page open the dataset's splits, the split's examples, the first example's valid fields and conditions, its card and the result for the current model are filled in. The refresh chain is dataset -> split -> example -> card -> show; changing a control re-runs its own step and every later one (field starts at card; ablation and model start at show); **Random example** picks an example and continues from the example step. `show` ends every chain and only looks in the result cache: it shows the stored result for this model and question, or "Not run yet for **<model>** on this question. Press Run." and empty panes, so changing the question never leaves an old result on screen and flipping between models that already ran is instant (in either tab). Both also return the responses table: one row per cached run of the question (model, prompt field, ablation, response, correct), in run order; no table when nothing has run on it. **Run** returns the cached result if there is one, else loads the model (freeing the previous one, and loading its refit lens if it has one), generates, renders one page per lens and stores the result; the cache keeps every model's results for the current question (keyed by prompt field and ablation too) and is cleared by the first Run on another question. Only `show` and Run share the model queue slot (`MODEL_QUEUE`), so two tabs never load or run at once and a model change made during a Run is shown after it. The model dropdown lists only the session profile (`--model` / run.yaml) and its adapters; the clamp ablations are offered only if that profile's readout statistics file exists.

Reading the result: generation still runs the full `max_new_tokens`, and the summary's response line and correct/incorrect use the full response (as eval does), but the heatmap stops at the answer token: the first generated token that, decoded, is not whitespace, a bare quote, EOS or a filler word from `evaluation.scoring.FILLER_PREFIXES` (" a", " the", " called", ...); if none qualifies it is token 0. The summary names its position. jlens pins at most 8 ids on page load (lowest ids first); with several English variants, answers and Chinese spellings some may start unpinned, but they are still tracked and can be pinned by clicking. The summary's last line is the replay check: whether the final layer's top-1 at each position, from the single forward over prompt + shown response, reproduces the generated token. On GPU bf16 a near-tie can flip between generation (one growing sequence per step) and the replay (one full-length forward), so some positions may be listed; the heatmap then shows the replay's numbers at those positions. Rows at ablated layers show the post-edit residual, so under `bridge` the bridge is gone there by construction. Each model is read with the base model's prefit lens in the first tab and with its own refit lens (when fitted) in the second; the second tab's rows at ablated layers show the residual edited along the original lens's directions. The page logs a harmless `history.replaceState` SecurityError in the browser console: jlens saves its view state in the page URL, which a `srcdoc` iframe cannot do; rendering and clicks are unaffected.

- `app.py` — Gradio wiring only (no model or tensor code).
  - `AppContext` — `run` (RunConfig), `viz` (VizConfig), `eval_cfg` (EvalConfig), `session` (the only holder of the loaded model; never put in `gr.State`), `tokenizer` (the session profile's, for the question list), `has_stats` (its readout statistics file exists), `choices` (label -> ModelChoice), `default_model` (a label), `rng` (for Random example), `dictionary` (Cedict, or None = no translation box), `cache` (`ResultCache`, process-wide, written only by `on_run`).
  - `MODEL_QUEUE` — shared `concurrency_id` / `concurrency_limit=1` for `show` and Run.
  - `on_dataset(ctx, dataset)` — split dropdown: `split_names` of the dataset's readable items, reset to `all`.
  - `on_split(ctx, dataset, split)` — the split's examples as `{name: TwoHopItem}` (kept in a per-tab `gr.State` so later events don't re-read the dataset) and the example dropdown, first selected.
  - `on_example(ctx, items, name, field, condition)` — field and ablation dropdowns limited to `valid_fields` / `buildable_conditions(ctx.has_stats, ...)`; the current choice is kept if still valid. No model needed.
  - `on_card(items, name, field)` — the example card (`page.item_card`).
  - `on_random(ctx, items)` — example dropdown set to `pick_random`.
  - `on_show(ctx, label, dataset, name, field, condition)` — cache lookup only (never touches `ctx.session`): `_outputs` for `RunKey(dataset, name, field, condition, label)` and its stored `Shown`, or the placeholder.
  - `on_run(ctx, label, dataset, items, name, field, condition)` — `_outputs` of the cached `Shown` if present, else of `_compute` (stored with `cache.put` first); `gr.Error` only if no example/field/ablation is selected.
  - `_compute(ctx, key, item)` — `session.get` (a `Loaded`) -> `run_example` with `loaded.js` -> `run_slices(loaded.js, loaded.readers, ...)` -> one `_pane` per reader titled by `_title` (`LENS_NAMES` = original, refit; the lens's `n_prompts`) -> `Shown`; `own` is `_no_lens_pane` (the `fit_command` note) when the model has no refit lens. The summary is prefixed with a `**Model:** <label>` line (so a stored result names its model); the replay check uses the original lens's slice.
  - `_outputs(ctx, key, shown)` — the result widgets' values in `_ResultArea.components` order: `responses_table(cache.entries(key.question))`, then `shown`'s summary, original and own panes, or the "Not run yet" placeholder and two empty panes when `shown` is None.
  - `_pane(ctx, slice_data, result, title)` — `iframe(_page(...))`. `_page(ctx, slice_data, result, title)` — `slice_page`, wrapped in `with_glosses(page, gloss_payload(...))` when `ctx.dictionary` is loaded (so each lens's page carries its own payload).
  - `build_app(ctx)` — the `gr.Blocks`: `_controls` lays out the components, `_wire` connects them.
  - `_controls(ctx)` — the layout from row builders `_source_row` (dataset, split), `_example_row` (example, Random), `_prompt_row` (field, ablation), the card, `_model_row` (model, Run) and `_result_area()`.
  - `_result_area()` / `_ResultArea` — the one place that knows the result layout: the responses table (`gr.Markdown`), the summary, and `gr.Tabs` with "Original lens" and "Refit lens (this model)", each a `_page_html()` pane. `_ResultArea.components()` lists them in `_outputs` order (the outputs of `show` and Run). Gradio mounts an inactive tab's content only when it is selected.
  - `_steps` / `_cascade` / `_tail` / `_chain` — the refresh chain (dataset -> split -> example -> card -> show) as an ordered list of event kwargs (each with an `api_name`); a trigger (`gr.on`) runs from its step to the end with `.success`, so a failed step stops the chain and every chain ends in `show`. Only user `.input` events start chains, never `.change`.
  - Embedding: `gr.HTML(js_on_load=None, apply_default_css=False)` holding `page.iframe`'s `<iframe srcdoc>`. Gradio 6 renders `value` raw through `innerHTML` (no sanitising); the `${value}` template inserts it as a JS variable, so `${...}` and backticks inside the page are never re-evaluated. The iframe's inline height sets its size.
- `run_app.py` — entry point.
  - `parse_args(argv=None)` — `model.cli.add_profile_args` (`--config --model --device`) plus `--viz_config`.
  - `build_context(args)` — `resolve_profile`, `load_viz_config`, `profile_choices`, default = the base choice of the session profile, `has_stats` = `jspace.profile_stats_path(profile, jspace_config(run)).exists()` (file existence only, `TODO(debt)`), `tokenizer` = `model.loading.load_tokenizer(profile)` (no model is loaded at startup), `EvalConfig()` defaults (debt-002), `Session(make_loader(run, args.device))`, `random.Random(eval_cfg.seed)`, `load_dictionary(viz.dictionary_file)`, an empty `ResultCache()`.
  - `profile_choices(run, viz, profile_name)` — `model_choices` restricted to the session profile (`--model` / run.yaml) and its adapters, with `with_refit_lenses(..., viz.lenses_dir)`, keyed by label; raises if the profile has no prefit lens. One profile per viewer process (`TODO(debt)`).
  - `load_dictionary(path)` — `load_cedict(path)` and prints `CC-CEDICT: <entries> entries, <headwords> headwords <- <path>`; `None` prints `Translations off (dictionary_file: null)` and returns None.
  - `main()` — `build_app(build_context(...)).launch(server_name, server_port, show_error=True)`.
